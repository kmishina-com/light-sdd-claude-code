# サイクル（またはタスク）を閉じる

引数: $ARGUMENTS

1つ目の語がプランのパス、残りが人が確かめた結果である。

## 止まる条件

次のどれかに当たったら、コミットせずに止めて、何が足りないかを報告する。推測で埋めない。

- 完了基準の確認方法のうち、結果が無いものがある（自動の項目も、人が確かめる項目も）
- 受け入れ条件のうち、確認方法が1本も無いものがある
- 人の確かめた結果に「不合格」がある
- 作業ツリーに、プランの変更対象・新規作成・文書以外の変更がある

## 手順

1. 完了基準の確認方法のうち、自動の項目をもう一度実行し、出力をそのまま報告に貼る。
2. 受け入れ条件ごとに、満たしているか、どの確認方法で確かめたかを表にする。人が確かめた項目は「人が確認済み」と分かる形にする。
3. spec を更新する。
   - 未解決事項: 答えが出たものに「決定:」と理由を1行足す。項目は消さない。実装プランで決めたものは、結論とプランへの参照だけを書く。
   - 対象外: サイクル中に気づいて、今回は扱わないと決めたものを足す。
   - 書いた時点から誤っていた記述は直す。その時点では正しかった記述は書き換えず、追記する。
4. プランの「確認」に結果を記録する。観測した主体（人・Claude Code）と、合否を判断した主体を分けて書く。見ていない範囲と、それでも閉じてよい理由も書く。tasks があれば、そのタスクに完了の印を付ける。
5. コミットする。メッセージにはプランのパスを入れる。既存のコミットは書き換えない（amend しない）。
6. `git status` と `git log --oneline -5` の出力をそのまま報告する。

## 報告に書くこと

- 自動の項目の出力
- 受け入れ条件の最終判定の表
- spec と プランで更新した箇所
- コミットのハッシュと、コミット後の `git status`
- 実行しなかった指示（あれば）
